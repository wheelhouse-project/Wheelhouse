This is the automatically generated reference for every action a pattern step can perform, for the notices and windows that Wheelhouse shows, and for every user-facing setting that the shipped config.toml contains. Optional settings that the file leaves commented out are described in the help document instead. It is built from the same sources the application uses, so it stays in step with what Wheelhouse actually does. Every voice command is listed in the Voice Commands section of the help document (wheelhouse_help.md), which is also the guided introduction to using Wheelhouse; for installation, see the installation guide (wheelhouse_install.md).

Action Reference

Every action a pattern step can perform, generated from the action catalog that the Pattern Manager's action list and its help page read. Each entry gives the label the Pattern Manager shows, the action name that a pattern file uses, what the action does, its parameters in the order a pattern passes them, and a worked example. The word in parentheses after a parameter is its kind, which sets the field the Pattern Manager's editor shows for it: choice is a fixed list, group_ref is a list of the pattern's capture groups (g1, g2, and so on) that also accepts typed text, and every other kind is a text field.

A trigger can capture a number with (\d+). Wheelhouse changes this capture when it loads the pattern, in a command pattern (the trigger starts with ^) and in a replacement pattern (no ^). The capture then matches digits and spoken number words, so "delete 3" and "delete three" both match. An action that takes a count converts the captured value, so "seven" and "7" give the same result.

If Wheelhouse cannot convert the words in the first (\d+) capture to a number, the pattern does not match. Wheelhouse does not check a second or later (\d+) capture in the same pattern. Write (\d+), not a list of number words, because the speech engine can send digits or words.

A replacement pattern writes the captured number as the user spoke it. With the trigger page (\d+) and the text page number g1, "page seven" writes "page number seven" and "page 7" writes "page number 7". "page zero" and "page 0" also match.

The words "for", "to", and "too" also match a (\d+) capture. The words before and after the match stay, so "turn the page for me" types "turn the page number for me". To prevent this, start the trigger with ^. Then the trigger must be the whole utterance.

A "number" or "numbers" word before the value is part of the capture, so "page number seven" writes "page number number seven". Do not repeat the word "number" in the output text when users can say it.

AI

Ask AI

Action name: ask_ai. The Pattern Manager lists it under Advanced actions, AI.

Sends one prompt to the configured AI and stores its reply for a later step. Capture groups and earlier step results substitute into the prompt; failures stop the pattern.

Parameters, in the order a pattern passes them:

  • prompt (text) -- Question or instruction for the AI. It may include a capture group or an earlier step's result name.

It stores the text it produces for the steps after it: a later step's parameter that is exactly ask_ai, or exactly the result name set on this step, receives that text.

Example: Trigger "^ask (.+)$" with params ["Answer in one short sentence, no preamble: g1"] and result "answer", then use params ["answer"] in a following insert_text step.

Cancel AI fix

Action name: cancel_fix. The Pattern Manager lists it under Advanced actions, AI.

Cancels an in-progress AI text correction before it pastes anything back.

Parameters: none.

Example: Trigger "^cancel fix$" with no params: saying "cancel fix" stops the running correction.

Fix text with AI

Action name: fix_text_ai. The Pattern Manager lists it under Advanced actions, AI.

Captures the selected text, or all the text in the focused field when nothing is selected, sends it to the configured AI for correction, and pastes the corrected version back.

Parameters: none.

Example: Trigger "^fix(?:ed)?$" with no params: saying "x-ray fix" or "x-ray fixed" corrects the selected text, or all the text in the focused field when nothing is selected.

Rewrite text with AI

Action name: rewrite_text_ai. The Pattern Manager lists it under Advanced actions, AI.

Captures the selected text, or all the text in the focused field when nothing is selected, sends it to the configured AI to be rewritten in the style you describe, and pastes the rewritten version back. You write the style sentence and nothing else: Wheelhouse adds the wording that keeps the layout intact and the wording that stops the highlighted text from redirecting the AI.

Parameters, in the order a pattern passes them:

  • instruction (text) -- One sentence describing the style, addressed to the AI, ending with "Return only the rewritten text." For example: "Rewrite this text in plain language. Keep every fact. Return only the rewritten text."

Example: Trigger "^simplify$" with params ["Rewrite this text in plain language. Keep every fact. Return only the rewritten text."]: saying "simplify" by itself rewrites the highlighted text in plain language.

Clicking

Click a control by name

Action name: click_element. The Pattern Manager lists it under Advanced actions, Clicking.

Finds a control in the focused window by its spoken name (optionally with a role word like button) and clicks it.

Parameters, in the order a pattern passes them:

  • target (group_ref) -- Capture group holding the spoken control name, usually g1.

Example: Trigger "^(?:click|clicks|tap)\s+(.+)$" with params ["g1"]: saying "click submit button" clicks the button labeled Submit. This one needs no safety word.

Hide numbered click overlay

Action name: hide_overlay_command. The Pattern Manager lists it under Advanced actions, Clicking.

Removes the numbered badges painted by the show-numbers command.

Parameters: none.

Example: Trigger "^(?:hide|hyde|dismiss|dismissed) numbers$" with no params: saying "hide numbers" hides the badges. "hyde numbers", "dismiss numbers", and "dismissed numbers" do the same.

Hide the numbers and the grid after Escape

Action name: escape_hides_numbers_and_grid. The Pattern Manager lists it under Advanced actions, Clicking.

Hides the numbered badges and the mouse grid; put it after the step that presses Escape. With key words it hides only when Escape is the only key they name, whatever the count.

Parameters, in the order a pattern passes them:

  • key_sequence (group_ref) -- Optional spoken key words, the capture group g1 of the press-keys trigger; the hide runs only when Escape is the only key they name, in any spelling press_keys reads. Leave it out to always hide.
  • repeat (group_ref) -- Optional spoken count, the capture group g2 of the press-keys trigger; any count still hides.

Example: Trigger "^(?:escape|dismiss|dismissed)$" with params ["esc"] for press and no params for this step: saying "escape" presses the Escape key and then hides the numbers and the grid. "dismiss" and "dismissed" do the same.

Right- or double-click a control by name

Action name: click_element_command. The Pattern Manager lists it under Advanced actions, Clicking.

Parses a full gesture click command (right click X, double click X) and clicks the named control with that mouse gesture.

Parameters, in the order a pattern passes them:

  • utterance (group_ref) -- Capture group holding the whole spoken command including the gesture words, usually g1.

Example: Trigger "^((?:right|double)[\s-]+click\s+.+)$" with params ["g1"]: saying "right click recycle bin" opens the context menu of the Recycle Bin icon.

Show numbered click overlay

Action name: show_overlay_command. The Pattern Manager lists it under Advanced actions, Clicking.

Paints a number badge on every clickable control on screen so you can say "click" plus a number.

Parameters: none.

Example: Trigger "^(?:show numbers|apply numbers|show numbers here)$" with no params: saying "show numbers" shows the badges; then "click four" clicks control number 4. "apply numbers" and "show numbers here" do the same.

Clipboard

Capture clipboard

Action name: capture_clipboard. The Pattern Manager's action list does not offer this action.

Reads the current clipboard text and stores it under the name capture_clipboard for a later step to use.

Parameters: none.

It stores the text it produces for the steps after it: a later step's parameter that is exactly capture_clipboard, or exactly the result name set on this step, receives that text.

Example: Trigger "^search$" copies the selection, calls capture_clipboard, then gs uses the stored value as the search query.

Skip clipboard restore

Action name: skip_clipboard_restore. The Pattern Manager's action list does not offer this action.

Marks this utterance so the original clipboard content is not restored afterward; used as the first step of copy and cut commands.

Parameters: none.

Example: First step of "^copy$": [skip_clipboard_restore, then hk ctrl+c] so the copied text stays on the clipboard.

Date and pauses

Format the current date

Action name: date. The Pattern Manager lists it under Advanced actions, Date and pauses.

Formats the current date and time and stores the result under the name date for a later step to insert.

Parameters, in the order a pattern passes them:

  • format (text) -- Python strftime format string (for example %Y-%m-%d); defaults to the ISO date.

It stores the text it produces for the steps after it: a later step's parameter that is exactly date, or exactly the result name set on this step, receives that text.

Example: Steps [{date, params ["%Y-%m-%d"]}, {insert_text, params ["date"]}]: inserts today's date, like 2026-07-09.

Pause between steps

Action name: sleep. The Pattern Manager lists it under Advanced actions, Date and pauses.

Waits the given number of seconds before the next action step runs.

Parameters, in the order a pattern passes them:

  • seconds (number) -- How long to wait, in seconds; fractions like 0.5 are allowed.

Example: Steps [{run, params ["notepad.exe"]}, {sleep, params ["1.5"]}, {type_text, params ["hello"]}]: waits 1.5 seconds for Notepad to open before typing.

Keyboard

Move the cursor by voice

Action name: cursor_navigate. The Pattern Manager lists it under Advanced actions, Keyboard.

Parses a spoken navigation phrase like "go right two words" and executes it as keystrokes; unrecognized phrases fall through to dictation.

Parameters, in the order a pattern passes them:

  • utterance (text) -- The navigation phrase, normally the template "go g1" so the words spoken after "go" are parsed.

Example: Trigger "^go (.+)" with params ["go g1"]: saying "go home then grab to end" moves to line start then selects to the end of the line.

Press a hotkey

Action name: hk. The Pattern Manager lists it under Basic actions.

Presses several keys together as one combination, optionally repeated a number of times.

Parameters, in the order a pattern passes them:

  • keys (keys) -- Key names held down together, listed in order (for example ctrl, z).
  • repeat (number) -- Optional last value: how many times to press the combination (capped at 30); often a capture group like g1 so the spoken number is used.

Example: Trigger "^undo\s*(\d+)?$" with params ["ctrl", "z", "g1"]: saying "undo three" presses Ctrl+Z three times.

Press a spoken key sequence

Action name: press_keys. The Pattern Manager lists it under Advanced actions, Keyboard.

Turns spoken key names into a key combination and presses it; if any name is unrecognized the whole phrase falls through to dictation.

Parameters, in the order a pattern passes them:

  • key_sequence (keys) -- Space-separated spoken key names in any order (for example control alt delete); usually the capture group g1.
  • repeat (number) -- Optional repeat count (capped at 30); the capture group g2 in "press tab three times".

Example: Trigger "^press\b\s*(.+?)(?:\s+(\d+)\s+times?)?$" with params ["g1", "g2"]: saying "press control alt delete" presses Ctrl+Alt+Delete, and "press tab three times" presses Tab three times.

Press one key

Action name: press. The Pattern Manager lists it under Advanced actions, Keyboard.

Presses a single key, optionally repeated a number of times.

Parameters, in the order a pattern passes them:

  • key (key) -- The key to press (for example del or backspace).
  • repeat (number) -- Optional repeat count (capped at 50); often a capture group like g1.

Example: Trigger "^delete\s*(\d+)?$" with params ["del", "g1"]: saying "delete three" presses the Delete key three times.

Mouse grid

Dismiss the mouse grid

Action name: grid_dismiss_command. The Pattern Manager lists it under Advanced actions, Mouse grid.

Closes the mouse grid without clicking anything.

Parameters: none.

Example: Trigger "^(?:hide|dismiss|dismissed) grid$" with no params: saying "hide grid" removes the grid. "dismiss grid" and "dismissed grid" do the same.

Mouse-grid action word

Action name: grid_action_command. The Pattern Manager lists it under Advanced actions, Mouse grid.

Runs one grid-only action word (mark, drag, or move_here) at the center of the grid that is on the screen; with the grid closed the word types as normal dictation.

Parameters, in the order a pattern passes them:

  • action (text) -- Fixed action name: mark, drag, or move_here.
  • utterance (group_ref) -- Capture group holding the spoken word for the dictation fallback, usually g1.

Example: Trigger "^(mark[.!?]?)$" with params ["mark", "g1"]: with the grid open, saying "mark" pins the drag start point; with it closed, "mark" just types the word.

Mouse-grid bare click

Action name: grid_click_command. The Pattern Manager lists it under Advanced actions, Mouse grid.

Clicks at the center of the open mouse grid on the screen (click, tap, right click, double click, or triple click); with the grid closed it clicks at the current pointer position. The words type as dictation only when voice clicking is turned off; say "literal click" to type the word.

Parameters, in the order a pattern passes them:

  • utterance (group_ref) -- Capture group holding the spoken gesture words, usually g1.

Example: With the grid narrowed to the target, saying "right click" opens the context menu at the cell center; with no grid open, saying "triple click" selects the line under the pointer.

Mouse-grid number

Action name: grid_number_command. The Pattern Manager lists it under Advanced actions, Mouse grid.

Narrows the open mouse grid to the spoken cell (one to nine). With the grid closed and the numbered overlay showing, the number clicks the control with that label; with neither showing, the number types as normal dictation.

Parameters, in the order a pattern passes them:

  • utterance (group_ref) -- Capture group holding the whole spoken text for the dictation fallback, usually g1.
  • number_word (group_ref) -- Capture group holding just the number word or digit, usually g2.

Example: Saying "five" with the grid open zooms the grid into cell 5; with the grid closed and the numbered overlay showing it clicks the control labeled 5; with neither showing it types "five".

Move the mouse grid to the next monitor

Action name: grid_next_screen_command. The Pattern Manager lists it under Advanced actions, Mouse grid.

Moves the open mouse grid to the next monitor, resetting it to cover that whole screen.

Parameters: none.

Example: Trigger "^grid next screen$" with no params: saying "grid next screen" jumps the grid to the other monitor.

Show the mouse grid

Action name: grid_show_command. The Pattern Manager lists it under Advanced actions, Mouse grid.

Opens the 3x3 mouse grid over the focused monitor; spoken numbers then narrow it to a point you can click, drag, or move to.

Parameters: none.

Example: Trigger "^(?:show|apply) grid$" with no params: saying "show grid" or "apply grid" paints the grid; "five" then "click" clicks the center.

Programs and web

Google search

Action name: gs. The Pattern Manager lists it under Advanced actions, Programs and web.

Opens a Google search for the given query in the default browser.

Parameters, in the order a pattern passes them:

  • query (text) -- Search text; may be a capture group, or the name of an earlier step whose stored result to search for (for example capture_clipboard).

Example: Trigger "^search$" copies the selection, captures the clipboard, then calls gs with params ["capture_clipboard"]: saying "search" by itself Googles the selected text.

Open a web address

Action name: open_url. The Pattern Manager lists it under Advanced actions, Programs and web.

Opens a web address in the default browser. Spoken words and earlier step results substitute into the address URL-encoded, so the address itself must start with http:// or https:// -- anything else fails the step and stops the pattern. The site part of the address (everything from http:// or https:// up to the first slash, question mark, or number sign) must be written out in the pattern: a capture group or result name there fails the step, and so does a capture group that did not match any spoken words. The address must use the normal form -- http:// or https:// followed directly by the site name, with no extra slashes and no control characters.

Parameters, in the order a pattern passes them:

  • url_template (text) -- The full web address, starting with http:// or https://. Capture groups (g1) or an earlier step's result name embedded in it are replaced with their text, URL-encoded so the spoken words arrive as data.

Example: Trigger "^jira (.+)$" with params ["https://mycompany.atlassian.net/issues/?jql=text~%22g1%22"] searches Jira for the spoken words.

Run a program

Action name: run. The Pattern Manager lists it under Basic actions.

Launches a program or command line on the computer.

Parameters, in the order a pattern passes them:

  • command (path) -- Program path or command line to run, including any arguments (for example explorer.exe ms-settings:).

Example: Trigger "^Windows? settings$" with params ["explorer.exe ms-settings:"]: saying "windows settings" opens the Windows Settings app.

Run a program and capture its text

Action name: run_capture. The Pattern Manager lists it under Advanced actions, Programs and web.

Runs a program without a shell and stores the text it prints for a later step. An optional leading, unquoted TOML number sets the timeout in seconds and is clamped from 0.1 to 60; failures, including output over the configured cap, stop the pattern.

Parameters, in the order a pattern passes them:

  • timeout (number) -- Optional leading timeout in seconds. It must be an unquoted TOML number and is clamped from 0.1 to 60 seconds. A quoted number is not a timeout; in the leading position it is used as the program path.
  • program (path) -- Program path to run. It is run directly, without a shell.
  • argument (text) -- Repeatable program argument. Add one separate field for each argument; no shell parsing is performed.

It stores the text it produces for the steps after it: a later step's parameter that is exactly run_capture, or exactly the result name set on this step, receives that text.

Example: Trigger "^look up (.+)$" with params [0.5, "C:\\Tools\\lookup.exe", "g1"] and result "answer", then use params ["answer"] in a following insert_text step.

Switch to a window

Action name: activate. The Pattern Manager lists it under Basic actions.

Brings a window to the front, found by program name (a target ending in .exe) or by the spoken name matching whole words in the window title; the reserved target default_browser resolves to your default browser.

Parameters, in the order a pattern passes them:

  • target (exe_or_title) -- Program executable name (notepad.exe), the words to find in a window title (whole words, plain text), or the reserved word default_browser.

Example: Trigger "^notepad$" with params ["notepad.exe"]: saying "notepad", and nothing else in that utterance, focuses the Notepad window.

Scrolling

Scroll the mouse wheel

Action name: scroll. The Pattern Manager lists it under Advanced actions, Scrolling.

Turns the mouse wheel a number of notches, up, down, left or right, without moving or pressing the mouse.

Parameters, in the order a pattern passes them:

  • direction (choice: up, down, left, right) -- Which way to turn the wheel.
  • clicks (number) -- Optional last value: how many wheel notches to send (capped at 50); often a capture group like g1 so the spoken number is used.

Example: Trigger "^scroll down\s*(\d+)?$" with params ["down", "g1"]: saying "scroll down three" turns the wheel three notches down.

Start scrolling and keep going

Action name: start_continuous_scroll. The Pattern Manager lists it under Advanced actions, Scrolling.

Starts turning the mouse wheel over and over, in one direction, until a stop command arrives or the time limit is reached.

Parameters, in the order a pattern passes them:

  • direction (choice: up, down, left, right) -- Which way to keep turning the wheel.

Example: Trigger "^start scrolling down$" with params ["down"]: saying "start scrolling down" scrolls down until you say "stop scrolling".

Stop the scrolling

Action name: stop_continuous_scroll. The Pattern Manager lists it under Advanced actions, Scrolling.

Stops a scroll that was started with the continuous scroll command. It takes no direction and does nothing when no scroll is running.

Parameters: none.

Example: Trigger "^stop scrolling$" with no params: saying "stop scrolling" ends the scroll that is running.

Text

Insert blank lines

Action name: insert_newlines. The Pattern Manager lists it under Advanced actions, Text.

Inserts the given number of newline characters (up to 50).

Parameters, in the order a pattern passes them:

  • count (number) -- How many newlines to insert; capped at 50.

Example: Trigger "^blank lines (\d+)$" with params ["g1"]: saying "blank lines three" inserts three newlines.

Insert raw text

Action name: insert_raw. The Pattern Manager lists it under Advanced actions, Text.

Inserts exact text at the cursor via paste, with no added space, capitalization, or cleanup.

Parameters, in the order a pattern passes them:

  • text (text) -- The exact characters to insert; may be a capture group like g1.

Example: Trigger "^insert\b\s*(.+)$" with params ["g1"]: saying "insert TODO:" inserts "TODO:" exactly, no leading space.

Insert text

Action name: insert_text. The Pattern Manager lists it under Basic actions.

Inserts text at the cursor with intelligent spacing and capitalization.

Parameters, in the order a pattern passes them:

  • text (text) -- The text to insert; may be a capture group like g1 to insert the spoken words.

Example: Trigger "literal (.+)$" with params ["g1"]: saying "literal submit" inserts the word "submit" as text instead of firing the submit command.

Insert text with no spaces

Action name: insert_raw_no_spaces. The Pattern Manager lists it under Advanced actions, Text.

Inserts text at the cursor via paste with every space removed, and no added space, capitalization, or cleanup.

Parameters, in the order a pattern passes them:

  • text (text) -- The words to join; may be a capture group like g1.

Example: Trigger "^no space (.+)$" with params ["g1"]: saying "no space hello world" inserts "helloworld".

Numbered list item

Action name: number_point. The Pattern Manager lists it under Advanced actions, Text.

Converts a spoken number to the digit followed by a period, for numbered lists.

Parameters, in the order a pattern passes them:

  • number (number) -- The number; usually the capture group g1.

Example: Trigger "^item (\d+)$" with params ["g1"]: saying "item five" inserts "5.".

Replace matched words with text

Action name: text. The Pattern Manager lists it under Advanced actions, Text.

The standard replacement action: inserts the given text with intelligent spacing, and an empty value silently discards the matched words.

Parameters, in the order a pattern passes them:

  • template (text) -- Replacement text; may reference capture groups; an empty string swallows the match (used to filter phrases like "okay Google").

Example: Trigger "\bperiod\b" with params ["."]: saying "period" during dictation inserts "." instead of the word.

Select a spoken phrase

Action name: select_phrase. The Pattern Manager lists it under Advanced actions, Text.

Finds the first match of the spoken words in the focused text control and selects it. The match is exact apart from letter case.

Parameters, in the order a pattern passes them:

  • phrase (text) -- The words to find; may be a capture group like g1.

Example: Trigger "^select (.+)$" with params ["g1"]: saying "x-ray select brown fox" selects the first "brown fox" in the document. This one needs the safety word first.

Spoken number as digits

Action name: number_digits. The Pattern Manager lists it under Advanced actions, Text.

Converts a spoken number to its digits, with no period.

Parameters, in the order a pattern passes them:

  • number (number) -- The number; usually the capture group g1.

Example: Trigger "^(?:numeric|numeral) (\d+)$" with params ["g1"]: saying "numeric twenty three" inserts "23", and the synonym "numeral seven" inserts "7".

Transform selected text

Action name: transform_selection. The Pattern Manager lists it under Advanced actions, Text.

Changes the currently selected text: case conversion (snake case, title case, and so on) or wrapping in quotes or brackets.

Parameters, in the order a pattern passes them:

  • transformation (choice: quote, single_quote, bracket, parenthesis, angle_bracket, curly_bracket, uppercase, lowercase, capitalize, title_case, snake_case, camel_case, pascal_case, kebab_case, compress) -- Which transformation to apply to the selection.

Example: Trigger "^snake case$" with params ["snake_case"]: with "hello world" selected, saying "snake case" replaces it with "hello_world".

Type captured words literally

Action name: literal. The Pattern Manager lists it under Advanced actions, Text.

Types the captured words exactly as spoken, bypassing all pattern processing and smart spacing.

Parameters, in the order a pattern passes them:

  • text (group_ref) -- The words to type, usually the capture group g1.

Example: Trigger "^say (.+)$" with params ["g1"]: saying "say hello" types "hello" with no command matching or cleanup.

Type text exactly

Action name: type_text. The Pattern Manager lists it under Advanced actions, Text.

Types text character for character with no smart spacing or capitalization.

Parameters, in the order a pattern passes them:

  • text (text) -- The exact text to type; may be a capture group like g1.

Example: Trigger "^find\s*(.*)$" presses Ctrl+F then calls type_text with params ["g1"]: saying "x-ray find hello" opens Find and types "hello".

Wrap in delimiters

Action name: wrap_or_insert. The Pattern Manager lists it under Advanced actions, Text.

Wraps the selection or the captured words in the given delimiters, or inserts an empty delimiter pair with the cursor between when there is nothing to wrap.

Parameters, in the order a pattern passes them:

  • left_fence (text) -- Opening delimiter (for example ( or ").
  • right_fence (text) -- Closing delimiter (for example ) or ").
  • text (group_ref) -- Capture group holding the words to wrap (usually g1); may be empty.

Example: Trigger "\bparentheses(.*)$" with params ["(", ")", "g1"]: saying "parentheses hello" inserts "(hello)"; saying just "parentheses" wraps the selection or inserts "()".

Wheelhouse

Check for updates

Action name: check_for_updates. The Pattern Manager lists it under Advanced actions, Wheelhouse.

Opens the About Wheelhouse window and checks GitHub for a newer release. The check runs even when the automatic check is off.

Parameters: none.

Example: Trigger "^check for updates?$" with no params: saying "check for updates" opens the About Wheelhouse window and checks.

Open online help

Action name: wheelhouse_help_online. The Pattern Manager lists it under Advanced actions, Wheelhouse.

Opens the Wheelhouse Assistant at the assistant_url address under [ai.help] in the default browser. By default a short explanation window comes first, and its Assistant button opens the browser. When assistant_url is blank, a notice says that online help is not configured and nothing opens.

Parameters: none.

Example: Trigger "^help$" with no params: saying "help" opens the help page.

Open the Pattern Manager

Action name: open_pattern_manager. The Pattern Manager lists it under Advanced actions, Wheelhouse.

Opens the Pattern Manager window for viewing and editing voice patterns.

Parameters: none.

Example: Trigger "^patterns?$" with no params: saying "patterns" opens the Pattern Manager.

Open the Settings window

Action name: open_settings_window. The Pattern Manager lists it under Advanced actions, Wheelhouse.

Opens the settings window, where the menu settings and a few more can be changed with the mouse or by voice.

Parameters: none.

Example: Trigger "^settings?$" with no params: saying "settings" opens the settings window.

Set speech interaction mode

Action name: set_speech_interaction_mode. The Pattern Manager's action list does not offer this action.

Switches how the microphone is engaged: click to talk (toggle) or push to talk.

Parameters, in the order a pattern passes them:

  • mode (choice: toggle, push_to_talk) -- The interaction mode to switch to.

Example: Trigger "^push to talk mode$" with params ["push_to_talk"]: saying it switches the microphone to push-to-talk.

Stop listening

Action name: stop_listening. The Pattern Manager lists it under Advanced actions, Wheelhouse.

Switches listening off, as clicking the floating button or the tray icon does while it listens. In toggle mode, say the wake word to switch it back on; while sound that this computer plays keeps listening paused, click the floating button or the tray icon instead. In push-to-talk mode the wake word ends only the idle pause, so hold the floating button again.

Parameters: none.

Example: Trigger "^stop listening$": saying it by itself switches listening off.

Teach word to speech engine

Action name: add_hint_to_stt. The Pattern Manager's action list does not offer this action.

Sends the clipboard text to the speech engine as a recognition hint, so that the engine writes the word correctly. Only an engine that applies hints accepts this action. Google always applies hints. Parakeet, the default engine, applies hints only when hint biasing is on. Under another engine, Wheelhouse types the spoken words as dictation.

Parameters: none.

Example: Trigger "^boost$": select a word, and say "boost" by itself. When the engine applies hints, Wheelhouse copies the word and sends it to the engine as a hint. Otherwise, Wheelhouse types "boost".

Your training word

Action name: open_lead_word. The Pattern Manager lists it under Advanced actions, Wheelhouse.

Opens the training-word window, where you record the word 'hello' once so that WheelHouse keeps the first sound of a phrase after a pause. Only the Parakeet speech engine uses it.

Parameters: none.

Example: Trigger "^record my training word$" with no params: saying "record my training word" opens the training-word window.

Configuration Reference

General

SPEECH_WEBSOCKET_HOST (default: "127.0.0.1") -- The network address on which Wheelhouse's speech connection server listens. The default 127.0.0.1 accepts connections from this computer only. Change it only for the advanced setup in which speech recognition runs on a second computer on your home network. That setup also needs ws_host under [stt], which is the address that the speech engine connects to. The shipped file does not contain this key.

REPLACEMENT_TIMEOUT_MS (default: 700) -- The time in milliseconds that Wheelhouse waits after you stop speaking, before it decides that a correction phrase is complete. Raise it to 900-1000 if corrections start before you finish. This is common on slower machines. Lower it slightly if responses feel slow.

COMMAND_TIMEOUT_MS (default: 700) -- The time in milliseconds that Wheelhouse waits after you stop speaking, before it decides that a command phrase is complete. Raise it to 900-1000 if commands start before you finish. This is common on slower machines. Lower it slightly if responses feel slow.

GREEDY_TIMEOUT_MS (default: 5000) -- A longer wait, in milliseconds, for commands that listen for more words on purpose. You rarely need to change it.

COMMAND_COMPLETION_WAIT_MS (default: 1000) -- Has no effect. No part of Wheelhouse reads this setting. If you change it, nothing changes. To give commands more time, change COMMAND_TIMEOUT_MS.

ENABLE_AUDIO_SUPPRESSION (default: "auto") -- Pause listening while this computer plays sound, when the microphone has no echo canceller. Valid values: "auto", true, false. "auto" asks Windows once at startup if the default microphone and the default communications microphone have an echo canceller. It pauses when Windows reports none on one of them or cannot answer. Set true to pause whenever sound plays. Set false to never pause. With false and no echo canceller, expect more misrecognitions, because the microphone picks up the sound. On a machine where Windows reports no echo canceller, sound from a screen reader also pauses listening.

ENABLE_SONOS_SUPPRESSION (default: true) -- Pause listening while Sonos music plays. Disable it only if you want Wheelhouse to listen during playback. Expect more misrecognitions, because the microphone picks up the audio.

ENABLE_IDLE_SUPPRESSION (default: true) -- Pause listening after the computer becomes idle. Disable it only if you never want idle pauses. The Idle Monitor plugin sets when the pause starts.

LOG_FILE (default: "") -- Has no effect. No part of Wheelhouse reads this setting. Wheelhouse always writes its activity log to wheelhouse.log in its install folder, %LOCALAPPDATA%\Wheelhouse\app.

LOG_LEVEL (default: "INFO") -- How detailed the activity log is. Change only when a support conversation asks you to.

LOG_TRANSCRIPTS (default: false) -- A privacy setting. When false, the log files do not contain the words you dictate or your clipboard contents. The log files record only the length of the text. Set it to true only while you troubleshoot recognition. Then set it to false again. While it is on, everything that you dictate goes into the logs. This includes passwords.

SAVE_ENGINE_AUDIO (default: false) -- A privacy setting to diagnose a missing first sound. When true, the Parakeet v3 speech engine saves one sound file for every phrase that you say, in the folder %LOCALAPPDATA%\WheelHouse\engine-audio. While the Parakeet v3 engine runs, it deletes each of these files that is over 2 days old, at engine start and once an hour. While the engine does not run, the files stay. When you uninstall Wheelhouse, the uninstaller deletes the folder, also when you keep your personal data. The files stay on this computer. Set it to true only while a support conversation or a bug investigation asks for the sound files. Then set it to false again. While it is on, the files hold everything that you say. A change takes effect when the speech engine next starts. An engine switch or a Wheelhouse restart starts the engine.

CHECK_FOR_UPDATES (default: true) -- This setting controls if Wheelhouse asks api.github.com once a day if a newer release exists. When one exists, a notice offers to install it. Set false to stop the automatic update check. Wheelhouse then makes no automatic update request. A manual check from the About Wheelhouse window still sends one request when you ask for it. Without this key, the check is on.

SIDE_OFFSET (default: 10) -- Width in pixels of the left-edge screen zone where the mouse thumb wheel adjusts brightness instead of volume. Raise it if the brightness zone is hard to hit.

BRIGHTNESS_INCREMENT (default: 1.0) -- The size of each thumb-wheel brightness adjustment step. Raise it for faster, coarser changes. Lower it for finer control.

VOLUME_INCREMENT (default: 1) -- The size of each thumb-wheel volume adjustment step. Raise it for faster, coarser changes. Lower it for finer control. Use a whole number when the volume goes to a Sonos speaker, because the Sonos speaker drops the fraction.

THUMB_WHEEL_DEAD_ZONE_TICKS (default: 3) -- How many thumb-wheel ticks a gesture must reach before the brightness or volume zone acts. Wheelhouse holds the ticks below this number. The batch that reaches it releases them. Every later tick in the same gesture acts at once. Raise it if the wheel still reacts to an accidental touch. Set it to 1 to make every tick act at once.

THUMB_WHEEL_GESTURE_GAP_MS (default: 500) -- The pause, in milliseconds, that ends a thumb-wheel gesture. After a longer pause, the next touch starts in the dead zone again. Wheelhouse also forgets any held ticks. Raise it if a slow, deliberate roll keeps stopping early. Lower it if a stray tick still adds up with the next touch.

THUMB_WHEEL_MAX_TICKS_PER_BATCH (default: 3) -- The maximum number of thumb-wheel ticks that one 50 ms batch can apply to brightness or volume. Wheelhouse discards the ticks above this number in a single batch. So a fast flick moves at most this many ticks per batch. Raise it for larger changes from a fast roll. Lower it if a flick still jumps too far.

BRIGHTNESS_STEPS_PER_COMMAND (default: 2) -- The maximum number of native TV brightness steps that one thumb-wheel command can carry. The TV answers one command at a time, about 400 ms each for a Samsung. So this number is how far brightness moves per round trip while the wheel turns. Wheelhouse discards the ticks beyond it, so the TV does not continue to move after the wheel stops. Set it to 1 for the smoothest one-step-at-a-time change. Raise it if brightness moves too slowly. A value below 1 counts as 1.

FLOATING_BUTTON_SIZE (default: 50) -- Size in pixels of the small on-screen status button. If you drag the outer edge of the button, or hold Ctrl and roll the mouse wheel over it, Wheelhouse writes this setting.

FLOATING_BUTTON_POS (default: [100, 100]) -- Screen position of the small on-screen status button, as [x, y] pixels from the top-left of the desktop. If you drag the button, Wheelhouse writes this setting. It also writes this setting when you resize the button, because the button grows and shrinks around its own centre.

FLOATING_BUTTON_VISIBLE (default: true) -- This setting controls if the small on-screen status button appears. Set true for an always-visible microphone click target. In push-to-talk mode the floating button is the only way to listen, because the hold works on it alone.

SPEECH_ENABLED_ON_STARTUP (default: true) -- This setting controls if Wheelhouse starts to listen as soon as it launches. Set it to false to enable the microphone yourself each session.

INTERIM_RESULTS (default: true) -- This setting controls if Wheelhouse shows words while you speak, before the speech engine finishes the sentence. The Interim Results item in the right-click menu and in the Settings window changes this setting and saves it. Set false to see words only after the speech engine finishes each sentence. Without this key, or with a value that is not true or false, the setting is on.

SHOW_SPEECH_PULSE (default: true) -- Make the floating button pulse while Wheelhouse hears you. This shows that your speech reaches Wheelhouse. The tray icon does not pulse. With this setting off, the button still flashes green after Wheelhouse processes an utterance. Disable it only if the animation distracts you.

SPATIAL_SOUND_EXEC (default: "") -- The path to the small free NirSoft helper tool that Wheelhouse uses to switch Dolby Atmos spatial sound by voice. An empty value means that the feature is off. Type the tool path only if you use Dolby Atmos and you have that tool installed. Everyone else can ignore this setting.

SPATIAL_SOUND_FORMAT (default: "Dolby Atmos for home theater") -- The spatial sound format name that Wheelhouse passes to the helper tool. Only matters if SPATIAL_SOUND_EXEC is set.

[brightness_coordinator]

software_dimmer (default: "gamma_dimmer") -- The method that dims the screen with software. Wheelhouse uses it when hardware brightness is as low as it goes, and for every brightness step when no plugin controls the brightness of a screen. Valid values: "gamma_dimmer" (darkens the screen image, including the mouse pointer, through the Windows display brightness curve), "overlay" (a translucent overlay window), or "software_dimmer" (the same overlay window as "overlay"). Any other value falls back to "gamma_dimmer" with a warning in the log. Change it only if the screen does not dim correctly with your monitor setup.

unwinding_threshold (default: 10) -- This setting currently has no effect. Wheelhouse returns control to the hardware only after the software no longer dims the screen at all, regardless of this setting.

[plugins.internal_panel]

enabled (default: true) -- Turns the Internal Panel plugin on or off. The plugin controls the brightness of the built-in screen of a laptop from the brightness scroll zone. On a desktop PC with no built-in panel, the plugin does nothing. It is safe to leave it enabled.

[plugins.sonos]

enabled (default: false) -- Turns the Sonos plugin on or off. The plugin adjusts the volume of Sonos speakers from the volume scroll zone. It also pauses listening while music plays. Enable it only if you own Sonos speakers.

polling_interval (default: 2) -- How often, in seconds, Wheelhouse checks if music plays.

[plugins.system_volume]

enabled (default: true) -- Turns the System Volume plugin on or off. The plugin controls the normal Windows volume from the volume scroll zone. It also mutes system audio during push-to-talk holds.

device_type (default: "default") -- Which audio device to control. Valid values: "default" (the usual choice) or "communications".

volume_step_db (default: 0.75) -- Loudness change, in decibels, for each unit of VOLUME_INCREMENT. One wheel step sends VOLUME_INCREMENT units, so with the defaults (0.75 and 1) one step changes the loudness by 0.75 dB.

min_volume_db (default: -96.0) -- The volume floor, in decibels.

max_volume_db (default: 0.0) -- The volume ceiling, in decibels.

[plugins.bravia]

enabled (default: false) -- Turns the Bravia plugin on or off. The plugin adds a Sony Bravia TV that you use as a monitor to the brightness control of Wheelhouse. Enable it only if a Sony Bravia TV is your monitor.

ip_address (default: "") -- The address of your TV on the home network. If you leave it blank, Wheelhouse searches the network for the TV automatically. Set it if you have more than one TV or discovery fails.

psk (default: "") -- The pre-shared key that you set on the TV under Settings -> Network -> Home Network -> IP Control. The plugin does not start if this key is blank.

device_name (default: "SONY TV") -- The audio device name of the TV, exactly as Windows shows it under Sound settings -> Output. It is a device lookup key that the spatial sound feature uses. It is not a free-form label.

[plugins.idle_monitor]

enabled (default: true) -- Turns the Idle Monitor plugin on or off. The plugin pauses listening when you leave the computer. Wheelhouse starts to listen again when you return or say the wake word. Almost everyone should leave this on.

idle_timeout_minutes (default: 10) -- The number of minutes without keyboard or mouse activity after which Wheelhouse pauses listening.

polling_interval_seconds (default: 4) -- How often, in seconds, the plugin checks for idleness.

[plugins.window_positioning]

enabled (default: true) -- Turns the Window Positioning plugin on or off. The plugin moves the Windows On-Screen Keyboard out of the way when it would cover the window that you work in.

target_window_names (default: ["On-Screen Keyboard", "osk"]) -- Which windows the plugin moves. The default is the On-Screen Keyboard.

move_cooldown_seconds (default: 0.5) -- The minimum number of seconds between moves. This prevents jitter.

clearance_gap_pixels (default: 5) -- The gap in pixels between the moved window and the window that it covered.

ignore_window_titles (default: ["Program Manager", "Task Switching", "SoftwareDimmerOverlay_AlphaBlend_v12", "MainWindow"]) -- Window titles that never cause a move.

ignore_window_classes (default: ["Shell_TrayWnd", "Progman"]) -- Window classes that never cause a move.

[wake_word]

enabled (default: true) -- Turns wake-word listening on or off. In toggle mode, you can say the wake word out loud to start listening again. With the mode key at its default, "idle_recovery", this works whenever listening is off. It does not work during the sound pause or while a program holds the speaker in exclusive mode. With mode = "push_to_talk", it works only after the idle pause or the Sonos pause. The speech toggle, not the wake word, ends the sound pause, because the sound itself can say the wake word. In push-to-talk mode, the wake word ends only the idle pause, whatever the mode value. While a program holds the speaker in exclusive mode, the wake word does not end the pause, whatever the mode value.

keyword (default: "computer") -- The wake word.

sensitivity (default: 0.5) -- Wake-word detection sensitivity, range 0-1. Lower it if the wake word often fails to wake Wheelhouse. Raise it if ordinary conversation often wakes Wheelhouse by accident.

mode (default: "idle_recovery") -- Which pauses Wheelhouse listens for the wake word in. The value works the same in either interaction mode. "idle_recovery" listens whenever listening is off. This includes the idle pause, the sound pause, the Sonos pause, and a start with listening off. It also includes listening that you turned off yourself, for example with "stop listening". "push_to_talk" listens only during the idle pause, the sound pause, and the Sonos pause. So the wake word cannot undo "stop listening" or a start with listening off. What the wake word then does depends on the interaction mode. The wake word turns listening on in toggle mode, except during the sound pause. The wake word does not end the sound pause. The speech toggle ends it, and so does the end of the sound. The wake word ends only the idle pause in push-to-talk mode. After that pause, the next hold of the floating button is the way back. Neither value ends the pause while a program holds the speaker in exclusive mode. That pause ignores the wake word. Valid values: "idle_recovery" or "push_to_talk"; any other value turns the wake word off for every pause, and the log gives no warning about it.

model_dir (default: "../shared/data/wake_words") -- The location of the wake-word listening model on disk. The installer sets it. Do not change it.

[ui_actions.timing]

clipboard_verification_timeout_ms (default: 250) -- How long, in milliseconds, Wheelhouse waits for the clipboard to contain the new text when it inserts text. On older or heavily loaded machines, a higher value can fix text that arrives garbled, half-pasted, or out of order.

clipboard_operation_delay_ms (default: 50) -- Delay, in milliseconds, between clipboard operations during text insertion. On older or heavily loaded machines, a higher value can fix text that arrives garbled, half-pasted, or out of order.

selection_clear_delay_ms (default: 20) -- The delay, in milliseconds, after Wheelhouse clears a selection during text insertion. On older or heavily loaded machines, a higher value can fix text that arrives garbled, half-pasted, or out of order.

context_gather_delay_ms (default: 10) -- The delay, in milliseconds, before Wheelhouse gathers the text context around the caret. On older or heavily loaded machines, a higher value can fix text that arrives garbled, half-pasted, or out of order.

post_paste_delay_ms (default: 30) -- The delay, in milliseconds, after Wheelhouse pastes text into the target application. On older or heavily loaded machines, a higher value can fix text that arrives garbled, half-pasted, or out of order.

paste_landing_wait_ms (default: 500) -- How long, in milliseconds after a paste into Notepad, Wheelhouse waits for the dictated text to appear. If the text does not appear in that time, Wheelhouse pastes once more. On a heavily loaded machine, raise this if Notepad sometimes shows a dictated word twice. A higher value makes a lost word arrive later.

utterance_clipboard_timeout_seconds (default: 60.0) -- A safety limit, in seconds. Wheelhouse puts dictated text on the clipboard to paste it, and restores your own clipboard contents when the utterance ends. If the signal that shows the end of the utterance never arrives, Wheelhouse ends the utterance after this long and restores your clipboard.

[ui_actions.verified_unicode]

max_chars (default: 50) -- Wheelhouse types dictations up to this length directly, character by character. This does not use your clipboard. Wheelhouse uses the clipboard for longer dictations. Lower it if a particular app mishandles text that Wheelhouse types directly. Raise it so that more dictations bypass the clipboard.

[ui_actions.foreground_check]

same_process_browser_names (default: ["brave.exe", "brave_beta.exe", "chrome.exe", "chromium.exe", "msedge.exe", "edge.exe", "vivaldi.exe", "opera.exe", "operagx.exe", "arc.exe"]) -- The web browsers that Wheelhouse recognizes. Browsers manage their windows in an unusual way. The list already contains all the mainstream browsers.

same_process_browser_names_extend (default: []) -- Adds an unusual browser to the recognized list. You do not need to retype the built-in browsers.

[ui_actions.text_target]

allow_class_names_extend (default: []) -- Extends the built-in list of window classes that can receive dictation. Add a window here when you want Wheelhouse to type your short phrases into it key by key. Wheelhouse pastes your words into a box that it does not recognize, and it asks you nothing. In some apps Wheelhouse never types your words key by key, whatever you add here. It never types long text either.

deny_control_types_extend (default: []) -- Extends the built-in list of control types to which Wheelhouse denies dictation. Add a control here when Wheelhouse types into something that is not a text box. Wheelhouse then pastes your words there and does not type them, so the words still arrive.

deny_class_names_extend (default: []) -- Extends the built-in list of window classes to which Wheelhouse denies dictation. Add a window here when Wheelhouse types into something that is not a text box. Wheelhouse then pastes your words there and does not type them, so the words still arrive.

browser_process_names_extend (default: []) -- Extends the built-in list of browser process names that the dictation safety check uses. Add a browser here when Wheelhouse types into the page itself, which scrolls the page. Wheelhouse then pastes your words. It does not type them.

[speech]

interaction_mode (default: "toggle") -- The microphone interaction mode. The value toggle keeps the microphone on until you disable it. The value push_to_talk listens only while you hold the floating button. It also mutes system audio during the hold. Valid values: "toggle" or "push_to_talk". You can also switch by voice (push to talk mode / click to talk mode). You do not need to edit anything.

ptt_safety_timeout_seconds (default: 30) -- In push-to-talk mode, this releases the microphone automatically if a hold gets stuck. Raise it if you routinely dictate longer than 30 seconds in one hold.

notify_on_revision (default: false) -- Show a small notice when the speech engine revises its guess at what you said.

[stt]

last_provider (default: "parakeet_tdt") -- The speech-to-text engine that Wheelhouse uses. You normally switch engines from the menu on the floating button or the tray icon. Wheelhouse then writes your choice here for you. That is why Wheelhouse calls it the last provider. Valid values: "parakeet_tdt" (local, offline, no account) or "google_stt" (Google Cloud; needs an account, sends audio to Google).

[stt.google]

credentials_file (default: "") -- The full path to the Google service-account key file. This is the JSON file that you download during Google Cloud setup. Type the path here yourself and double each backslash. Then restart Wheelhouse. When this value is empty, Wheelhouse uses the GOOGLE_APPLICATION_CREDENTIALS environment variable instead.

[ai]

enabled (default: true) -- The master switch for all AI features. These features are dictation text correction, the rewrite commands, and Ask AI. This switch turns those commands on and off together. It also gates the in-app help chat, which is currently disabled. New installs leave it off unless you chose the AI helper during setup.

knowledge_base (default: "knowledge/wheelhouse_help.md") -- The document that the in-app help assistant would consult. The in-app help chat is currently disabled, so this setting has no effect today.

[ai.server]

base_url (default: "http://127.0.0.1:8781/v1") -- The address of the AI server that Wheelhouse talks to. Wheelhouse uses the standard OpenAI-style interface. An empty value leaves AI off. Any OpenAI-compatible address works, local or hosted. The installer's local AI choice writes http://127.0.0.1:8781/v1, and only its cloud choice fills in Google's Gemini address.

model (default: "gemma-4-e4b") -- The model name to request from the AI server. Change it to the name of a model on your server.

kind (default: "local") -- This setting says if the AI server is on your own machine or on the internet. This choice describes the privacy tradeoff. With a local server, the text that the server corrects never leaves your computer. Valid values: "local" or "cloud". This setting does not decide where your text is sent -- base_url above does that. Capitals and stray spaces are forgiven; anything else falls back to local and says so in the log.

timeout_s (default: 30) -- The number of seconds that Wheelhouse waits for the AI server before it stops a request. Raise it if a slow local model times out again and again.

[ai.runtime]

enabled (default: false) -- This setting controls if Wheelhouse starts its own model server. False means that you start one yourself and point base_url at it. Valid values: true or false. When true, base_url above must be a plain http address on 127.0.0.1 or localhost, with a port from 1 to 65535, that ends in /v1 (for example http://127.0.0.1:8781/v1), with no query, fragment, user name or password. Any other form makes Wheelhouse log an error and start no local server; an external server at that address still works. The port Wheelhouse starts its server on comes from that address, so the two cannot drift apart. The installer sets this to true when it downloads a model for you. Set it to false if you prefer to run your own server, or point Wheelhouse at a hosted one.

model_path (default: "") -- The full path to the model file Wheelhouse loads. The installer writes this. Point it at a different model file to change which model answers. Nothing else has to change.

binary_dir (default: "") -- The folder holding llama-server.exe, the program that runs the model. The installer writes this. Change it if you moved the llama.cpp build, or to use a build made for different graphics hardware.

context_size (default: 8192) -- How much text the model can consider at once, in tokens. Raise it if you correct or rewrite long passages and the reply comes back cut short. A larger value uses more memory.

startup_timeout_seconds (default: 90) -- After Wheelhouse starts its model server, this is how long it waits for the server to report that it is ready. After this time, Wheelhouse stops the server. The AI features stay off until a later start succeeds. Wheelhouse checks the server every 60 seconds, and again when an AI request fails while the AI features are on. The first check after the timeout starts the server again. An AI command that you speak while the AI features are off does not start a check. After each failed start, the wait before the next start doubles, from 120 seconds to at most 600 seconds. After a start that succeeds, the next start waits at least 60 seconds. Raise it if a large model on a slow disk is not ready when the wait ends.

[ai.help]

assistant_url (default: "https://notebook.google.com/notebook/da51a404-67ec-4804-9ebe-83605df3e9cf/preview") -- The web address that Help on the menu and the spoken command "help" open in your browser. If you clear this value, both show a notice that online help is not configured. Release 1.2.1 and earlier named this setting gem_url. When you update with the installer, it renames the setting to assistant_url and replaces an old assistant address with the current one.

explain_before_open (default: true) -- This setting controls if a window that explains the Wheelhouse Assistant appears before your browser opens. The "Do not show this again" check box of the window sets this setting to false. If you set it back to true, the window appears again. While the setting is false and the file help_explainer_notebook_shown.toml is missing from the data folder next to the settings file, the window appears at every Help with the box already ticked. Only the Assistant button writes that file. So after Cancel, the window appears again at the next Help. To keep the window off, select Assistant with the box still ticked.

max_response_tokens (default: 800) -- Caps the length of an answer from the in-app help chat. That chat is currently disabled, so this setting has no effect today.

[click]

enabled (default: true) -- The master switch for voice clicking. It controls the click-something-by-name commands and the numbered overlay.

min_confidence (default: 0.4) -- How sure Wheelhouse must be before it clicks something by name. Raise it if it clicks the wrong thing. Lower it if it too often finds no match.

clear_winner_margin (default: 0.15) -- How clearly one candidate must beat the runner-up before Wheelhouse clicks it by name. With no clear winner, Wheelhouse shows the numbered overlay. It does not guess.

notice_max_names (default: 3) -- How many candidate names appear in the did-you-mean style notice.

overlay_badge_font_pt (default: 8) -- The size of the numbers that Wheelhouse draws in the overlay. Raise it if the numbers are hard to read.

overlay_badge_shadow (default: false) -- This setting controls if each overlay number casts a drop shadow. It is off by default. The border of the bubble already separates the number from the background. Enable it if the numbers blend into busy screen content.

overlay_badge_theme (default: "auto") -- The color of the speech bubbles of the numbered overlay. The value names the bubble's own color, not the system theme. The value light gives a white bubble with a black number. The value dark gives a near-black bubble with a white number. The value auto picks the opposite of the Windows theme, so that the bubbles are easy to see. Valid values: "auto" (follow the Windows theme, inverted for contrast), "light" (white bubble), or "dark" (near-black bubble). Set it to light or dark if the automatic choice blends into the apps that you use most.

overlay_keep_numbers (default: false) -- What the numbered overlay does after a click or a window change. The default is off, which copies Windows Voice Access. A successful click on a number removes all the numbers, and a change of the front window removes them too. The value on keeps the numbers on the screen. Wheelhouse then shows new numbers after a click and after every window or menu change. If you say "hide numbers", Wheelhouse removes the numbers either way. A change that you save in the Settings window applies to the next click or window change, with no restart. Enable it if you click several numbered controls in a row and you want the numbers to stay.

response_timeout_ms (default: 3000) -- How long, in milliseconds, Wheelhouse waits for the search of a click command. After that time, Wheelhouse stops the search. Raise it on a slow machine if clicks time out in complex windows.

walk_deadline_ms (default: 2500) -- How long, in milliseconds, Wheelhouse searches a window for the control that a spoken click names. After that time, Wheelhouse stops the search. Raise it on a slow machine if clicks time out in complex windows. Keep it more than 250 below response_timeout_ms. A value that does not keep this gap switches voice clicking off, and the log names this key.

screen_read_timeout_ms (default: 10000) -- How long, in milliseconds, Wheelhouse waits for a read of the window's clickable things (show numbers, the refresh after a focus change, and the re-read after a click). After that time, Wheelhouse stops the read. This is separate from response_timeout_ms, which limits a click reply. Raise it if the numbered overlay reports that it could not draw the numbers in windows that take several seconds to answer.

snapshot_ttl_seconds (default: 30) -- How long the numbered overlay's snapshot stays valid, in seconds.

browser_processes (default: ["brave.exe", "chrome.exe", "msedge.exe", "vivaldi.exe", "slack.exe", "discord.exe", "code.exe", "ms-teams.exe", "Teams.exe", "spotify.exe", "notion.exe", "obsidian.exe", "ChatGPT.exe"]) -- The browser-like apps (browsers, Slack, Discord, and similar) that need a deeper search for clickable elements.

browser_processes_extend (default: []) -- Adds a browser-like app to the deeper-search list. You do not need to retype the built-in entries. Add an app here if voice clicking cannot see controls inside it.

enable_screen_reader_flag (default: false) -- Tells apps that a screen reader is present. This makes some apps expose more clickable elements. Try true if an app hides its buttons. Note that some apps change their appearance when this is on.

grid_min_cell_px (default: 24) -- The smallest size, in pixels, that a mouse-grid cell can become. Spoken numbers do not make the grid smaller than that size. Lower it for finer pointer placement on a very high resolution screen. A cell this small already places the pointer within the precision of a click.

drag_duration_ms (default: 250) -- How long, in milliseconds, a mouse-grid drag takes to move from the marked point to the destination. Raise it if an application does not register the drag. Many applications ignore a pointer that moves too fast.

[actions]

output_cap_chars (default: 10000) -- The maximum number of characters that the captured text of a pattern step can hold. This text is the output that a run_capture program prints or the reply that an ask_ai step receives. Longer output makes the step fail. The step does not insert an incomplete piece of it. Raise it (up to the 15360 ceiling) if a legitimate script prints more. Lower it for a tighter guard against a runaway program that fills your document.

run_capture_timeout_default_s (default: 10) -- How many seconds a run_capture pattern step waits for its program to finish when the pattern gives no timeout number of its own. Raise it if your scripts legitimately run longer. The longest wait of any step is 60 seconds, because voice commands wait their turn while a step runs.
